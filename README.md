# Ghana Smart Service Operations Optimizer

**DCIT 204/308 Joint DSA Semester Project — University Campus Service Hub**

A Java + SQLite system that loads University of Ghana, Legon campus data
(locations, roads, service requests, resources) into 13 custom-built data
structures and runs search, sort, graph, greedy and dynamic-programming
algorithms over them — dispatch scheduling, shortest routes, minimum-cost
networks, and budget-constrained request selection — all driven from one
console menu. See [PRD_Ghana_Smart_Service_Optimizer.md](PRD_Ghana_Smart_Service_Optimizer.md)
for the full assignment brief this implements.

## Requirements

- **JDK 17+** (`java -version` / `javac -version`)
- **Maven 3.6+** (`mvn -v`)

Neither is required to be pre-installed system-wide — see below if you need
a quick portable setup.

## Quick start

```bash
mvn -q package -DskipTests
java -jar target/campus-service-hub-jar-with-dependencies.jar
```

On first run this automatically:
1. Creates `campus_hub.db` (SQLite) from [`src/main/resources/schema.sql`](src/main/resources/schema.sql) (6 tables).
2. Imports the seed dataset from [`data/`](data/) (50 locations, 110 roads, 30 resources, 300 service requests — see [`data/EVIDENCE_NOTE.md`](data/EVIDENCE_NOTE.md) for how it was generated).
3. Loads everything from the database into the custom data structures.
4. Opens the interactive console menu.

Subsequent runs reuse the existing `campus_hub.db` (including any
`algorithm_runs` / `audit_events` history) instead of re-seeding.

To start fresh: delete `campus_hub.db` and re-run.

## Console menu

```
1) Data & Database                 — reload structures from DB / re-import CSVs
2) Data Structures Demo            — hash table, AVL tree, B-tree, BST, FIFO/circular queue, deque, heap
3) Search & Sort Lab               — linear vs binary search, pick a sort algorithm to run
4) Graph Engine                    — BFS, DFS, Dijkstra, Prim MST, Kruskal MST
5) Optimisation Engine             — greedy resource assignment, greedy-vs-DP knapsack counterexample
6) Audit / Undo Log                — view/undo the stack-backed action log
7) Performance Experiment Lab      — runs the M10 timing experiments, writes results/*.csv + algorithm_runs table
0) Exit
```

Every operation in the PRD is reachable here — no code changes needed to
demo any structure or algorithm.

## Project layout

```
src/main/java/gh/edu/campushub/
  model/          domain objects (Location, Road, ServiceRequest, Resource, AlgorithmRun, AuditEvent)
  structures/      all 13 from-scratch data structures (see below)
  db/              JDBC connection, schema init, DAOs, CSV loader
  engine/          CampusDataStore (DB -> structures) and the stack-based AuditLog
  algorithms/
    search/        LinearSearch, BinarySearch
    sort/          SelectionSort, InsertionSort, MergeSort, QuickSort
    graph/         BFS, DFS, Dijkstra, Prim, Kruskal
    greedy/        GreedyResourceAssignment, GreedyKnapsack (the required greedy-failure counterexample)
    dp/            Knapsack (0/1, tabulation + reconstruction)
  experiments/     PerformanceLab (M10 timing harness)
  tools/           DatasetGenerator (regenerates data/*.csv)
  config/          TeamConfig (index-number-derived algorithm parameters)
  app/             Main, App (the console menu)
src/test/java/...   105 JUnit 5 tests mirroring the same package layout
data/                seed CSVs + EVIDENCE_NOTE.md
results/             raw performance-experiment CSVs (generated by menu option 7)
reports/             correctness_evidence.md (trace tables, proof sketches, counterexamples)
```

### The 13 data structures (all built from scratch — no `java.util` equivalents)

Dynamic array, linked list, stack, FIFO queue, circular queue, deque,
binary heap (priority queue), binary search tree, AVL tree (the brief's
simplified-balanced-tree alternative to red-black), B-tree (the brief's
DB-index-simulation alternative), hash table (separate chaining), hash set
(built on the hash table), disjoint set (union by rank + path compression),
and a graph maintaining both adjacency list and adjacency matrix.

## Regenerating the dataset

```bash
mvn -q compile
java -cp target/classes gh.edu.campushub.tools.DatasetGenerator
```

Deterministic — reruns produce byte-identical CSVs, seeded from
[`TeamConfig.RANDOM_SEED`](src/main/java/gh/edu/campushub/config/TeamConfig.java),
which is derived from the team's 14 index numbers (see `TeamConfig` Javadoc
for the exact formulas — the same seed also drives `PRIORITY_WEIGHT`,
`ROUTE_PENALTY_FACTOR`, and `HASH_TABLE_DEFAULT_CAPACITY`).

## Running the tests

```bash
mvn test
```

105 tests across every structure and algorithm, including the PRD's
required edge cases (empty structure, single element, duplicate keys,
disconnected graph, unreachable path, full/empty queue, hash collision) and
both required counterexamples (greedy failure, invalid binary-search
precondition) — see [`reports/correctness_evidence.md`](reports/correctness_evidence.md)
for the accompanying trace tables and proof sketches.

## Running the performance experiments

From the console menu, option `7`, then `7` again to run all six
experiments (search comparison, sorting comparison, hash load factor, BST
vs AVL, heap dispatch, graph algorithms). Each is run 3× and averaged, per
the PRD. Results land in both:

- `results/*.csv` — raw timings for plotting
- the `algorithm_runs` table in `campus_hub.db`
